# broca-wire approval read and status contracts

`run.status` remains `state: "active"` during an approval wait. Its optional
`awaiting_approval` contains only durably Deferred calls. An older marker can
supply a filing ID, but cannot keep an approved or closed call pending. The
field is omitted when there are no pending calls or the actor cannot report it.

## Late-approval pages on session.read

Late approvals are separate from conversation messages and never enter a model
prompt. The default page (no message continuation, or `from_ordinal: 0`) includes
`late_approvals` when the session has them. Ordinary message continuation pages
do not repeat those entries.

Two optional, additive fields page that separate stream:

- Request **`late_after`**: the opaque durable call key returned by an earlier
  page. Return only late entries strictly after that key, and **no messages**.
- Response **`next_late_after`**: when more late entries remain, pass this value
  as the next request's `late_after`. The last page omits it.

Transcript reads budget the **complete serialized reply body** against `max_bytes`,
including messages, late entries, tools, attribution, metadata and continuation
cursors. The default and maximum are both **3 MiB (3,145,728 bytes)**; larger
requests are capped to that maximum. Late entries share the message page's budget.
Each late entry is atomic. A single entry larger than the cap is returned whole,
**alone on its late page**; it is never truncated or dropped. The call-key order
is stable for a durable snapshot. New late records are observed by a new default
read; this is not a permanently pinned multi-request snapshot.

A nonempty page keeps at least one message and, when reporting late entries, one
late entry. Oversized atomic items, their combined minimum, or unpaged metadata
can still exceed the budget. `run.result` is unpaged and returns the final text
whole; the read budget does not bound it.

An unavailable cursor (including one removed by retention) is refused as a typed
`invalid_params` body with `detail.field: "late_after"`, not answered as an empty
page. For example:

```json
{"code":"invalid_params","message":"unknown late_after cursor 'gone:1'","detail":{"field":"late_after"}}
```

Requests without `late_after` retain existing message pagination. Sessions with
no approval records retain their legacy response bytes. A read whose WAL tail
is incomplete explicitly reports
`open_batch: {"state":"not_reported","reason":"incomplete_tail"}` and omits
unavailable approval lists. An explicit late continuation requiring that
unavailable metadata is an error rather than an empty late page.

The byte fixtures under `tests/golden/session_read.late_*` pin the default page,
continuation, final page and invalid cursor. `session_read.approvals.json` pins
open-batch call states and an indeterminate late outcome.

## Credential-scoped run errors and their fixtures

`billing_exhausted`, `account_limit_exhausted` and rate-limit `transient` terminals carry
`error.credential_id`, the full credential id the run froze (for example
`apikey:anthropic:work`), so a router can stop selecting that one key instead of the whole
provider. A rate-limit terminal's
`provider_code` is `rate_limited`. The `run_status.*` error goldens are generated by
`broca-module-serve`'s account-selection rig from the real daemon's `run.status` reply,
against a fake provider upstream.

`run_status.billing_exhausted_anthropic_apikey.json` is RECONSTRUCTED, NOT CAPTURED: its
upstream answers Anthropic's public out-of-credit shape, because no real refusal has been
recorded yet. The exact body is HTTP 400
`{"type":"error","error":{"type":"invalid_request_error","message":"Your credit balance is too low to access the Anthropic API. Please go to Plans & Billing to upgrade or purchase credits."}}`.
Replace it, the rig's `ANTHROPIC_CREDIT_BALANCE_BODY` and the transport tests' body with
the first real refusal. `run_status.transient_rate_limited_credential.json` answers a
rate-limit 429 the rig made up for the test, which is the ordinary Anthropic error shape.

## Retention expiry while approval withdrawals are owed

A retained session becomes expired at its retention deadline for reads and status,
including when a closed call still owes a question withdrawal. A new send at that
address creates a fresh lineage; it never reopens the expired transcript. The WAL
and its side files are deleted within `delete_within_ms` (3,600,000 ms), independently
of the question provider's availability.

Before deletion, owed withdrawals are transferred transactionally into identity-only
retention records: session and lineage identity, the frozen scope, durable call key,
question ID when known, provider identity, and ask expiry. Arguments, prompts, and
results are not retained. A separate worker withdraws known questions using the
stored scope. Scope/session-ended and unknown-question refusals settle the record;
retryable failures back off only until the original ask expiry. A lost filing response
remains `id_unknown`; it is never re-filed, and is dropped at ask expiry with one WARN
containing the session and call key, not conversation content.

The retained scope uses only explicit identity fields and known principal kinds.
An unknown owner or carrier principal is not copied, since its forward-compatible
JSON can contain arbitrary content. Its obligation remains explicitly unservable
until ask expiry, then is dropped with one session-and-call-key-only WARN.

# broca-wire

Client-facing session and run JSON contracts. Optional members are absent rather
than null when the durable record carries no value.

## Agent-run scope refusals

- `agent_run_scopes_unsupported`: terminal. A reader-only build can decode an
  agent-run scope but cannot freeze or advance a session under it, including an
  internal resume. `detail` names the scope; no WAL bytes are appended.
- `scope_run_mismatch`: terminal. A send changed a frozen agent-run identifier.
  `detail.field` is `run_id` or `agent_id`; no WAL bytes are appended.
- `scope_owner_mismatch`: the existing identity refusal for a wrong carrier or
  an owner attempting to drive an agent-run scope. Only `reserved:basal` may
  drive these model-only sessions.

`agent_run_scope_tests::agent_run_scope_refusal_bytes_are_pinned` pins the new
reply shapes. The broca daemon module advertises `agent-run-scopes/v1` to promise
admission of Basal's model-only run scopes, and requires that WAL feature for
frozen run identities. The unsupported refusal
remains decodable for older readers, but this writer no longer produces it.
